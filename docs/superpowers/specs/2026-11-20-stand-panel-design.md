# Панель стенда (v1): дизайн

## Задача

Простая веб-панель на Vue для наблюдения, отладки и управления стендом 5G + IMS + AI:
состояние и кнопки управления, проверки, журналы, SIP-диаграммы звонков, метрики и
графики. Изменение абонентов и `lab.env` из панели — следующий этап.

## Доступ

Панель слушает только `127.0.0.1:PANEL_PORT` (по умолчанию 8090), без входа.
Оператор открывает её через SSH-туннель: `ssh -L 8090:localhost:8090 kopatych`.
Сервер принимает только запросы с именем `127.0.0.1` / `localhost` в `Host` и любым
портом (защита от DNS rebinding; туннель может открыть панель на другом порту); изменяющие запросы требуют заголовок `X-Panel: 1` и
совпадающий `Origin` (защита от CSRF со сторонних страниц).

## Устройство

| Часть | Где | Что делает |
|---|---|---|
| сервер панели | `app/panel/server/lab_panel/` | Flask + waitress на хосте (venv `local/panel-venv`), служба systemd пользователя `lab-panel` |
| захват SIP | `app/panel/sipcap/` | контейнер `lab-panel-sipcap`: `network_mode: host`, только `NET_RAW`, AF_PACKET на всех интерфейсах, UDP SIP, кольцевой буфер в памяти, HTTP на `127.0.0.1:PANEL_SIPCAP_PORT` |
| интерфейс | `app/panel/web/` | Vue 3 + Vite + uPlot; сборка `dist/` (не в Git) раздаётся сервером |
| управление | `scripts/panel.sh` | `install`, `start`, `stop`, `status`, `sudoers` |

Захват SIP — отдельный контейнер вне проекта `lab-docker`: `stand.sh down` его не
останавливает. Один пакет виден на veth и на мосту (и дважды на `lo`) — дубликаты
отбрасываются по (адреса, порты, IP ID, хеш данных) в окне 2 с. TCP и фрагменты IP в
v1 не разбираются; трафик телефона внутри IPsec не виден.

## API

| Запрос | Ответ |
|---|---|
| `GET /api/status` | контейнеры по группам (ядро, IMS, AI, панель), процессы радио (наш gNB, rfsim, чужой), PLMN, доступность sudo без пароля, текущее задание, нагрузка хоста |
| `GET /api/actions` | список разрешённых действий |
| `POST /api/actions/<имя>` | запуск задания; 409, если идёт другое изменяющее задание |
| `GET /api/jobs`, `GET /api/jobs/<id>/stream` | последние 50 заданий; вывод задания (SSE) |
| `GET /api/logs/stream?sources=&tail=` | журналы контейнеров и файлов радио (SSE) |
| `GET /api/metrics?series=&since=` | точки рядов; `GET /api/metrics/series` — имена |
| `GET /api/calls?kind=`, `GET /api/calls/<call-id>` | диалоги SIP; сообщения диалога для диаграммы |

Действия — только из белого списка: `stand-up`, `stand-down`, `gnb-up`, `gnb-down`,
`rfsim-up`, `rfsim-down`, `stand-check`, `phones`, `sims`, `core-check`, `collect`,
`verify-all`, `verify:<проверка>` (отдельные `app/tests/integration/verify-*.sh`),
`restart:<контейнер>` (только запущенные `lab-*`, `oai-*`, `mysql`). Изменяющие
действия выполняются по одному; `sims`, `phones`, `core-check` — в любой момент.
Вывод заданий хранится в `local/panel/jobs/`.

## sudo

Скрипты стенда вызывают `sudo`. Задания панели получают в `PATH` обёртку
`app/panel/bin/sudo`, которая вызывает `sudo -n` (без пароля, без терминала);
`sudo -v` превращается в `sudo -n true`. Без правила sudoers кнопки радио показывают
«нужен sudo» и команду для терминала. `scripts/panel.sh sudoers` печатает правило
`/etc/sudoers.d/5g-lab` с полными путями. Правило фактически даёт права root
(`ip netns exec`, `env`, `nr-softmodem`), как и группа `docker`; это стенд, а не
продакшен. `verify-5g` без широкого правила пропускается (`sudo недоступен`).

## Данные

- **Журналы:** `docker logs -f --tail N --timestamps` по каждому источнику, слияние
  в один поток; файлы радио (`local/gnb/gnb.log`, `local/rfsim/*.log`) — чтение с
  конца. Строки, похожие на ключи, скрываются (`redact.py`).
- **SIP:** значения `nonce`, `response`, `cnonce`, `opaque`, `ck`, `ik`, `auts` и
  ключи SRTP заменяются на `***`.
- **Метрики:** каждые 10 с `docker stats` (CPU, память контейнеров), нагрузка и
  память хоста, число REGISTER/INVITE/отказов SIP за интервал; события журналов
  `AI`/`LLM`/`VOICE` с полями `*_ms` и `*_seconds`. Всё в памяти, 24 ч.

## Экраны

Верхняя строка: PLMN, ядро, IMS, AI, радио, текущее задание. Вкладки:

1. **Обзор** — карточки контейнеров (перезапуск), кнопки стенда и радио,
   подтверждение для выключения.
2. **Проверки** — запуск, живой вывод, строки PASS/FAIL/SKIP подсвечены, история.
3. **Журналы** — выбор источников, фильтр, пауза, «собрать журналы» (`collect`).
4. **Звонки** — таблица диалогов, лестничная диаграмма (UE, P-CSCF, I-CSCF, S-CSCF,
   SIP AS, Voice Agent и др.), клик — текст сообщения, режим «следить».
5. **Метрики** — графики uPlot за 15 мин / 1 ч / 6 ч / 24 ч.

Тема светлая и тёмная по системе.

## Проверка

Unit-тесты: разбор пакетов и SIP (sipcap), группировка диалогов, скрытие секретов,
белый список действий, разбор `docker stats` и событий AI. Локально — панель и
sipcap в Linux-контейнере на Docker Desktop с запущенным стендом.
