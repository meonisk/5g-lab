# Профилирование стенда: CPU и задержки перевода

Статус: дизайн согласован 12.11.2026 (вариант A). Ветка `partner-ims-ai`.

Второй подпроект доработки стенда. Даёт цифры для третьего — real-time перевода.

## Цель

Понять, что нужно, чтобы задержка «конец фразы → первый звук перевода» была не больше
**2 с** на CPU-сервере, где рядом работает rfsim (gNB и UE OAI). Сейчас на kopatych —
медиана ~4,9 с, из них распознавание Whisper base — ~3,6 с.

Готово, когда одна команда на стенде

```bash
scripts/profile.sh
```

создаёт `local/profile/<UTC>/` с `report.json` и `report.md`, где есть:

1. CPU каждого узла по каждому сценарию: среднее, p95, занятые ядра;
2. задержка по этапам перевода по каждому сценарию;
3. перебор настроек AI: время этапов и качество распознавания;
4. итог: узкое место и до трёх конфигураций, укладывающихся в 2 с при нагрузке rfsim,
   с ценой по CPU и качеству (или явная запись, что ни одна не укладывается).

## Что замеряется

### CPU по узлам

Раз в 0,5 с, без новых зависимостей:

- контейнеры стенда и ядра OAI — счётчик `cpu.stat` (`usage_usec`) их cgroup v2
  (путь — из `docker inspect`, cgroup v1 — `cpuacct.usage`);
- процессы rfsim (`nr-softmodem`, `nr-uesoftmodem`) — `utime + stime` из
  `/proc/<pid>/stat`;
- всего на хосте — `/proc/stat`; число ядер — `nproc`.

Для каждого узла: среднее и p95 занятых ядер (1,0 = одно ядро целиком) за сценарий.

### Задержка по этапам

Из событий сервисов, как в `scripts/bench_5g.py` (AI Worker `/events`, Voice Agent
`/status`): ожидание паузы (VAD), очередь, распознавание, перевод, синтез до первого
RTP, итог «конец речи → первый RTP ответа». Медиана, минимум, максимум по раундам.

### Сценарии

| # | Сценарий | Нагрузка |
|---|---|---|
| S1 | простой стенд | IMS + AI запущены, звонков нет |
| S2 | rfsim без звонков | `rfsim.sh up` |
| S3 | один звонок на 1003 без rfsim | SIPUE1 из сети ядра |
| S4 | один звонок на 1003 с rfsim | UE1 через 5G, как `bench_5g.py` |
| S5 | два переводимых звонка одновременно с rfsim | UE1 → UE2 (translate B2BUA) и SIPUE на 1003 |

Каждый сценарий — фиксированная длительность или N раундов фразы (по умолчанию 5);
S2/S4/S5 пропускаются с пометкой SKIP, если rfsim недоступен; S5 — если переводимый
звонок UE1 → UE2 не устанавливается.

### Перебор настроек AI

Без звонка, на записанной фразе: одноразовый контейнер из образа `lab-ai-worker` с
теми же моделями и ограничением CPU, как у сервиса, гоняет распознавание и перевод
напрямую. Варианты:

- модель Whisper: `tiny`, `base`, `small` (те, что есть в `local/models`; нет —
  SKIP с причиной);
- потоки распознавания `AI_STT_CPU_THREADS`: 1, 2, 4, 8 (не больше `nproc`);
- потоковый режим `AI_STREAMING_ENABLED`: 0 и 1 (время до первого частичного
  результата);
- пауза конца фразы `AI_UTTERANCE_SILENCE_MS`: 700, 500, 300 (вклад паузы считается
  арифметически, отдельного прогона не требует).

Каждый вариант — при простое и при запущенном rfsim (если доступен). Качество —
доля совпавших слов распознанного текста с эталоном (`1 − WER` по словам после
нормализации регистра и пунктуации). Эталон — текст синтезированных фраз
(`SIP_UE_TEST_UTTERANCE` и фразы русской стороны из фикстуры диалога
`app/tests/fixtures/`).

### Итог

Оценка задержки для варианта = пауза + распознавание + перевод + синтез (+ очередь из
сценариев). Вариант «укладывается», если медиана ≤ 2000 мс и качество не хуже
текущего `compact` более чем на 10 п.п. Отчёт перечисляет до трёх таких вариантов,
отсортированных по CPU.

## Реализация

- `scripts/profile.sh` — точка входа: проверка окружения, сценарии, перебор, отчёт;
  лог в ту же папку. Возвращает стенд в исходное состояние (`trap`): rfsim — как был
  до запуска, тестовые клиенты удалены, временные контейнеры удалены.
- Python-модули в `scripts/profile/` (сэмплер CPU, сценарии, перебор, отчёт) — каждый
  до 300 логических строк (`scripts/check.py`); разбор и статистика покрыты unit-тестами
  без Docker.
- Переиспользуется `bench_5g.py` (клиенты в namespace UE, события сервисов) — общие
  функции выносятся, а не копируются.
- Только stdlib Python и то, что уже есть в образах; адреса и параметры — из `lab.env`.

## Не входит

- сами оптимизации (подпроект real-time);
- `perf` / `py-spy` (вариант B) — точечно позже, если понадобится;
- GPU.
