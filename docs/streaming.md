# Экспериментальный потоковый перевод

**По умолчанию выключен.** Пока нет прогона, одновременно подтвердившего
1–3 секунды и полноту текста. Публикуемый профиль использует CPU STT и
пофразовую обработку. GPU включается только локальными overrides. Не включайте streaming для реальных разговоров.

Цель: первая слышимая часть перевода через 1–3 с **от начала речи**.
Пока инструментирован только интервал до отправки звучащего RTP. Он не равен
времени до динамика UE; успешный серверный гейт не доказывает пользовательский SLA.

`AI_STREAMING_ENABLED=1` включает режим только для `interpret_ru/interpret_en`.
Обычные транскрипция и помощник продолжают работать пофразово.

1. Assembler сохраняет нарастающий PCM-фрагмент, не отрезая слово по таймеру.
2. Каждые `AI_STREAM_INTERVAL_MS` предлагает снимок STT. Если для звонка ещё
   выполняется задача, устаревающий снимок пропускается; аудио остаётся в буфере.
3. Два соседних результата ASR должны совпасть по начальным словам.
   `AI_STREAM_MIN_WORDS` и `AI_STREAM_HOLDBACK_WORDS` задают минимальный префикс
   и число удерживаемых слов. Только новый суффикс отправляется в LLM.
4. Перевод озвучивается через существующую последовательную очередь Piper.
5. При конце речи последний ASR освобождает хвост. Изменение уже отправленного
   префикса и отказ доставки фиксируются как ошибка, а не маскируются повтором.

Стабильность ASR не гарантирует законченного смысла. Контекст перевода ограничен
историей звонка; качество частичных переводов нужно проверять отдельно. Также
нужно измерять отставание всех последующих фрагментов, а не только первого.

## GPU для STT

Whisper small остаётся той же моделью. Необходимые библиотеки CUDA/cuDNN
закреплены в Dockerfile; по умолчанию CPU-образ не скачивает их.
На настроенном NVIDIA Docker host задайте локальные overrides в
`local/secrets/ims.env` (не публиковать этот файл):

```dotenv
AI_ENABLE_CUDA=1
AI_CONTAINER_RUNTIME=nvidia
AI_GPU_DEVICES=all
AI_DEVICE=cuda
AI_COMPUTE_TYPE=int8_float16
AI_WORKER_MEMORY_LIMIT=4g
```

Пересоберите и пересоздайте `ai-worker`. Готовность объявляется после STT и LLM
warmup. GPU делится с Ollama; на другой видеокарте проверьте память и конкуренцию.
[Требования faster-whisper](https://github.com/SYSTRAN/faster-whisper#gpu).

## Проверка и откат

`scripts/run-interpreter-experiment.ps1` сохраняет полный вход/выход и метрики.
В streaming-режиме проверяются четыре завершённые исходные реплики, отсутствие
конфликта ASR, покрытие финального текста и первая задержка по каждой реплике
(`AI_STREAM_START_DELAY_LIMIT_MS`). Количество TTS-фрагментов не равно количеству
исходных фраз. Проверка покрытия слов не является проверкой смысла перевода.

CPU-пилот `20260919T205643Z-streaming-local-agreement-cpu` не прошёл порог:
первые ответы 5.28–8.61 с. Повторное STT оказалось дороже выигранного ожидания.
Его артефакты оставлены как FAIL. Для возврата к пофразовому режиму задайте
`AI_STREAMING_ENABLED=0` и пересоздайте `ai-worker`.

Исторические локальные GPU-прогоны от 19 сентября 2026 года
(RTX 4060 Ti 8 ГБ, Whisper small int8_float16). Приватные WAV и логи
не входят в репозиторий; таблица не заменяет повторный прогон на вашей машине:

| Прогон | Первые ответы от начала речи | Покрытие ASR | Итог |
| --- | --- | --- | --- |
| `20260919T210200Z-streaming-local-agreement-gpu` | 1.64–7.98 с | FAIL | FAIL |
| `20260919T210627Z-streaming-gpu-held-tail` | 1.47–4.83 с | PASS | FAIL |
| `20260919T210904Z-streaming-gpu-stable-prefix` | 1.42–2.96 с | FAIL | FAIL |

Последний вариант ускоряет начало, но при изменении уже выданного префикса
перестаёт выдавать хвост. Эта ошибка **не** замаскирована ослаблением проверки.
Следующий шаг — обработка пересмотров ASR с привязкой к времени/подтверждённым
словам и отдельный замер в приёмном аудиотракте. Также требуется устранить
накопление пауз при озвучке однословных фрагментов и проверить смысл переводов.
