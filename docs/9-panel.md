# 9. Панель стенда

Веб-панель для наблюдения, отладки и управления стендом: состояние ядра, IMS, AI и
радио, кнопки включения, проверки с живым выводом, журналы, SIP-диаграммы звонков и
графики. Изменение абонентов и `lab.env` из панели — следующий этап.

## Установить и открыть

На сервере стенда, в папке репозитория:

```bash
scripts/panel.sh install
```

Команда создаёт `local/panel-venv`, собирает интерфейс (`npm` на сервере или образ
`PANEL_NODE_IMAGE`), собирает образ захвата SIP и включает службу systemd
пользователя `lab-panel`. Панель слушает только `127.0.0.1:8090` и входа не имеет:
снаружи её не видно.

На своём компьютере:

```bash
ssh -L 8090:localhost:8090 kopatych
```

и откройте <http://localhost:8090>. Пока SSH-сеанс открыт, панель доступна.

| Команда | Что делает |
|---|---|
| `scripts/panel.sh install` | установить или обновить (после `git pull`) и запустить |
| `scripts/panel.sh start` / `stop` / `status` | служба и контейнер захвата |
| `scripts/panel.sh sudoers` | напечатать правило sudo для кнопок радио |
| `scripts/panel.sh run` | сервер в этом терминале (для разбора сбоев) |

Журнал самой панели: `journalctl --user -u lab-panel -n 50`.

## Кнопки радио и sudo

`stand.sh`, `gnb.sh` и `rfsim.sh` вызывают `sudo`. У панели нет терминала, поэтому
она вызывает `sudo -n` (без пароля). Пока правило не установлено, на кнопках радио и
включения стенда написано «нужен sudo» — эти действия можно выполнить в терминале.
Установить правило:

```bash
scripts/panel.sh sudoers | sudo tee /etc/sudoers.d/5g-lab
sudo chmod 440 /etc/sudoers.d/5g-lab && sudo visudo -cf /etc/sudoers.d/5g-lab
```

> **Безопасность.** Правило разрешает `ip netns exec`, `env` и `nr-softmodem` от root
> без пароля — по сути это права root для вашего пользователя, как и группа `docker`.
> Для отдельного сервера стенда это приемлемо; на общем сервере правило не ставьте.

`verify-5g` внутри «Все проверки» требует более широких прав (chroot) и без пароля
пропускается с причиной «sudo недоступен». Его запускайте из терминала.

## Вкладки

| Вкладка | Что там |
|---|---|
| **Обзор** | PLMN, контейнеры ядра, IMS, AI (перезапуск ↻), процессы радио, кнопки: включить/выключить стенд, gNB SDR, rfsim; «Телефоны в IMS», «SIM в UDR и PyHSS», «Настройка ядра» |
| **Проверки** | `stand_check.py`, `verify-all.sh` и отдельные проверки с живым выводом (PASS/FAIL подсвечены), история; вывод каждого задания — в `local/panel/jobs/` |
| **Журналы** | контейнеры и файлы радио (`local/gnb/gnb.log`, `local/rfsim/*.log`) в одном потоке, фильтр (регулярное выражение), пауза, «Собрать журналы» (`stand_check.py collect`) |
| **Звонки** | все SIP-диалоги стенда: звонки, регистрации, прочее; лестничная диаграмма (телефон, P-CSCF, I-CSCF, S-CSCF, SIP AS, …), клик по стрелке — текст сообщения; «следить за новыми» |
| **Метрики** | CPU и память контейнеров, SIP за 10 с (REGISTER, INVITE, BYE, отказы), нагрузка хоста, задержки AI по событиям (`llm_ms` и др.), длина фраз; 15 мин – 24 ч |

Изменяющие стенд действия выполняются по одному: пока идёт, например, `stand.sh up`,
остальные такие кнопки неактивны. Выключение стенда и gNB просит подтверждения.
Задание продолжается, даже если закрыть браузер или перезапустить панель.

## Что видно и что нет

- **Ключи не показываются.** В SIP значения `nonce`, `response`, `ck`, `ik` и ключи
  SRTP заменены на `***`; строки журналов, похожие на ключи, скрыты целиком.
  IMSI и номера видны: это нужно для отладки.
- **Захват SIP** — контейнер `lab-panel-sipcap` (сеть хоста, только право `NET_RAW`)
  видит UDP SIP на всех интерфейсах хоста: мосты Docker, veth, `lo`. Не видны SIP по
  TCP, фрагментированные пакеты и всё, что телефон шлёт внутри IPsec к P-CSCF: после
  P-CSCF звонок телефона виден полностью.
- **История** — в памяти: последние `PANEL_SIPCAP_MESSAGES` сообщений SIP и 24 ч
  метрик. Перезапуск панели обнуляет метрики, перезапуск захвата — звонки.
- `stand.sh down` не выключает панель и захват: панель показывает, что стенд
  остановлен, и может включить его снова.

## Если не работает

| Что видно | Что сделать |
|---|---|
| `ssh -L` открыт, страница не грузится | `scripts/panel.sh status`; `journalctl --user -u lab-panel -n 50` |
| «Интерфейс не собран» | `scripts/panel.sh install` (нужен `npm` или доступ к Docker Hub за `PANEL_NODE_IMAGE`) |
| «Захват SIP не отвечает» | `docker logs lab-panel-sipcap`; `scripts/panel.sh start` |
| кнопка радио: код 1, `a password is required` | правило sudo не установлено (раздел выше) |
| панель пропадает после выхода из SSH | `loginctl enable-linger $USER` (нужен sudo) |
