# Исследовательские SIM

[Назад к документации](README.md). Общие требования к телефону и текущие блокеры:
[native-phone.md](native-phone.md).

Партия из 10 программируемых USIM/ISIM для звонков с настоящих телефонов.
IMSI `901700000029600`–`901700000029609`, ICCID `8988211…`, тестовый PLMN
**MCC 901 / MNC 70** (MNC из двух цифр). Таблица поставщика содержит IMSI, ICCID,
ACC, PIN1/PUK1, PIN2/PUK2, Ki и OPc. Ключа администрирования ADM1 в ней нет,
поэтому перепрограммировать карты нельзя: стенд подстраивается под карты.

Ki/OPc и PIN/PUK в Git и документацию не попадают. Таблица хранится у оператора,
рабочий список — в игнорируемом `local/secrets/research-sims.csv`.

## Команды

Все команды выполняются из корня репозитория. Команды без `--apply` базы не меняют.

```bash
python scripts/research_sims.py import /путь/к/sim_imsi.xlsx   # 1. перенести нужные поля
python scripts/research_sims.py plan                           # 2. проверить, ключи не выводятся
python scripts/research_sims.py apply                          # 3. OAI UDR + PyHSS (локальное ядро)
python scripts/research_sims.py apply --ims-only               #    только PyHSS (ядро у партнёров)
python scripts/research_sims.py status                         # 4. только чтение: что есть в базах
python scripts/phone_readiness.py                              # 5. серверная готовность, включая SIM
```

`import` читает XLSX (первый лист) или CSV без дополнительных библиотек и
переносит только IMSI, ICCID, Ki, OPc, AMF (по умолчанию `8000`) и MSISDN.
PIN/PUK и ACC не переносятся. Повторный импорт требует `--force`.

Проверки при импорте и каждом запуске: IMSI из 15 цифр и из PLMN `lab.env`,
контрольная цифра ICCID, длина Ki/OPc/AMF, Ki ≠ OPc, отсутствие повторов,
отсутствие пересечений с UE1/UE2 и с номерами услуг `*_MSISDN`.

`scripts/start_lab.py` и `scripts/start_partner.py` вызывают `apply` сами после
заведения UE1/UE2, если список уже импортирован; без списка шаг пропускается.

Для OAI партнёров с MySQL UDR можно подготовить приватный SQL и передать его
по защищённому каналу:

```bash
python scripts/research_sims.py oai-sql --output local/private/research-sims-udr.sql
```

### Что записывается в базы

У физической карты один Ki/OPc, поэтому он используется дважды:

| База | Запись | Поведение при повторе |
| --- | --- | --- |
| OAI UDR | `AuthenticationSubscription` (5G AKA, Milenage), AM и SM-подписка с DNN `internet` и `ims` | Существующая запись не перезаписывается, SQN сохраняется; другие ключи — ошибка |
| PyHSS | AuC с ICCID, subscriber, IMS-subscriber с iFC по умолчанию | AuC не изменяется (PATCH сбросил бы SQN); другие ключи — ошибка; subscriber и IMS обновляются |

Номер SIM: `RESEARCH_SIM_MSISDN_PREFIX` + последние
`RESEARCH_SIM_MSISDN_SUFFIX_DIGITS` цифр IMSI, сейчас **2600–2609**. Номер
не зависит от порядка строк. Свой номер можно задать столбцом `MSISDN` в CSV.

Идентификаторы, которые телефон без записанного ISIM выводит из IMSI:

| Что | Значение для SIM `…29600` |
| --- | --- |
| IMPI | `901700000029600@ims.mnc070.mcc901.3gppnetwork.org` |
| IMPU | `sip:901700000029600@…` (временный), `sip:2600@…`, `tel:2600` |
| Realm | `ims.mnc070.mcc901.3gppnetwork.org` |

## Изменения lab.env

| Параметр | Было | Стало | Зачем |
| --- | --- | --- | --- |
| `MCC`, `MNC` | `001`, `01` | `901`, `70` | gNB должен вещать PLMN карты, AMF — обслуживать его |
| `IMS_DOMAIN` | `ims.mnc001.mcc001…` | `ims.mnc070.mcc901.3gppnetwork.org` | Телефон выводит домен из IMSI; Kamailio/PyHSS — из MCC/MNC |
| `UE1_IMSI`, `UE2_IMSI` | `00101…01/02` | `90170…01/02` | Виртуальные UE должны быть в том же PLMN, что gNB |
| `RESEARCH_SIM_*` | — | новые | Путь к приватному списку и правило номеров |

**Уже развёрнутый стенд.** OAI-конфигурация перерисуется при следующем
`initialize_local.py` или `start_lab.py`. В PyHSS останутся прежние UE1/UE2
с IMSI `00101…` и теми же номерами 1001/1002. Удалите их до запуска с новым PLMN:

```bash
python scripts/research_sims.py retire --imsi 001010000000001 --imsi 001010000000002          # план
python scripts/research_sims.py retire --imsi 001010000000001 --imsi 001010000000002 --apply  # удаление
```

Строки старых IMSI в UDR OAI ни с чем не конфликтуют и могут остаться.
Новый стенд с пустыми томами этого шага не требует.

## Что сделано заранее

- Список из 10 SIM проверен: все IMSI в PLMN 901/70, у всех ICCID верная
  контрольная цифра, ключи корректного формата и без повторов.
- PLMN, IMS-домен и IMSI виртуальных UE в `lab.env` переведены на 901/70.
- Заведение SIM в OAI UDR и PyHSS идёт с сохранением SQN и проверкой ключей
  существующих записей; шаг встроен в запуск локального и партнёрского стенда.
- `phone_readiness.py` проверяет наличие SIM в базах (`research_sims_provisioned`).
- `check-no-hardcoded-topology.py` не даёт IMSI, Ki и OPc карт попасть в исходники.

## Что проверить до первого звонка

Без телефона и радиосети этого не проверить:

1. **Чтение карты (по возможности).** Прочитать карту через PC/SC-ридер,
   например `pySim-read` (без ADM): длина MNC в `EF_AD` должна быть 2. Если 3,
   телефон получит домен `ims.mnc700…`, и `lab.env` придётся менять. Также проверить:
   содержимое ISIM (`EF_IMPI`, `EF_DOMAIN`, `EF_IMPU`) — если там уже записаны
   другие идентификаторы, нужно согласовать их с PyHSS; не включена ли защита SUCI
   (UST сервисы 124/125) — тогда OAI UDM нужен ключ домашней сети; включён ли PIN1.
2. **Радиосеть и ядро.** gNB вещает PLMN 901/70 и TAC `OAI_TAC`; AMF партнёров
   обслуживает 901/70; SIM заведены в их UDR (через `oai-sql` или их процедурой).
3. **PIN.** Если PIN1 включён, ввести его из таблицы поставщика или отключить в телефоне.
4. **Телефон.** Для PLMN 901/70 у Android обычно нет профиля оператора: могут
   отсутствовать переключатели VoLTE/VoNR и настройки IMS. Создать APN `internet`
   (тип `default`) и `ims` (тип `ims`), протокол IPv4: DNN стенда выдают только IPv4.
5. **SQN.** USIM и ISIM карты могут использовать общий счётчик SQN, а UDR и
   PyHSS ведут свои. Однократный Sync Failure с AUTS ожидаем; SQN в базах не сбрасывать.
6. **Известный серверный блокер.** P-CSCF/S-CSCF пока отклоняют обязательные
   `100rel`/`precondition`, которые штатные IMS-клиенты обычно требуют
   ([native-phone.md](native-phone.md)). Первая регистрация может пройти, а вызов
   из штатной звонилки — нет. Это следующая задача на стороне сервера.

Порядок приёмки на телефоне — [native-phone.md](native-phone.md#подключение-партнёров-и-порядок-проверки).
Номера для вызовов: SIM между собой 2600–2609; AI-услуги — `VOICE_*_MSISDN` (1003–1006).
