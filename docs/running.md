# 5g-lab: running the local 5G SA + IMS voice lab

Repository: [2508/5g-lab](https://git.miem.hse.ru/2508/5g-lab).
Run the commands below from the cloned `5g-lab` repository root.

The Docker Compose project identifier remains `lab-docker` for compatibility
with existing named volumes and research designs. It is an internal deployment
identifier, not the repository name. Renaming the clone directory does not
change it; changing the Compose identifier requires a separate volume migration.
Team development: [CONTRIBUTING.md](../CONTRIBUTING.md),
[project map](project-layout.md), [configuration](configuration.md).
Run `python scripts/quality/check.py` before submitting a change for review.

Implementation history: [changelog](../CHANGELOG.md).

This directory starts the complete local stand on Windows Docker Desktop/WSL2
or a native Linux Docker host:

- Open5GS 5GC, one UERANSIM gNB, and two UEs;
- `internet` and `ims` PDU sessions for each UE;
- IMS DNS, PyHSS, Kamailio P/I/S-CSCF, and two PJSUA subscribers;
- RTPengine media anchoring;
- an iFC/ISC-triggered SIP Application Server, RTP Media Adapter, local
  faster-whisper STT worker, and isolated Ollama/Qwen LLM;
- two native IMS services: Russian-to-English spoken translation on
  `VOICE_TRANSLATOR_MSISDN`, and explicit opt-in recording/transcription on
  `VOICE_TRANSCRIBER_MSISDN`;
- a two-leg interpreter room: the Russian participant calls
  `VOICE_INTERPRETER_RU_MSISDN`, the English participant calls
  `VOICE_INTERPRETER_EN_MSISDN`, and each receives only translated TTS in the
  participant's own language.

The media path copies only subscriber-originated PCMU from RTPengine, forms
bounded Russian/English utterances with VAD in memory, transcribes them with a
revision-pinned multilingual faster-whisper model, sends the transient text and
bounded per-call context to a SHA-256-verified local Unsloth Qwen3 4B Q4_K_M model, and
passes the bounded response to the TERMINATE Voice Agent. The current
lightweight TTS backend is local Piper (Russian Denis and English LJ Speech);
it returns PCMU RTP through
RTPengine to the IMS subscriber. Multiple turns are supported in one call, and
subscriber speech interrupts assistant playback, but not interpreter replies.
Ordinary subscriber-to-subscriber RTP is designed to remain operational if the
AI path is unavailable; AI-terminated services still depend on their workers.

## Configuration rule

All mutable topology, ports, pools, subscriber identities, and service timing
live in `app/config/lab.env`. Credentials and key material live only in the ignored
`local/secrets/ims.env`, generated by `scripts/initialize_local.py`. The example documents the required
keys; its placeholder values cannot be used to start the stand.

Do not call bare `docker compose`: interpolation requires both env files. Use:

```powershell
.\scripts\compose.ps1 ps
.\scripts\compose.ps1 logs -f sip-as voice-agent media-adapter ai-worker
```

or from Git Bash:

```bash
./scripts/compose.sh ps
```

`scripts/check-no-hardcoded-topology.py` rejects topology or subscriber
literals outside the two canonical env files.

## Start everything

Prerequisites: Docker with Linux containers, Python 3.12+ and Bash. Windows
uses Docker Desktop/WSL2 and Git for Windows; Linux requires an SCTP-capable kernel.

```powershell
.\scripts\start.ps1
```

On Linux use `./scripts/start.sh`. The common Python launcher loads or verifies
SCTP, builds/starts the full stack,
idempotently provisions Open5GS and PyHSS subscribers, restarts the UE clients,
and runs the nine shell gates listed in `scripts/start_lab.py`. The Python
bidirectional-interpreter and parallel-call checks below are additional checks;
the launcher does not run them. Use `-SkipVerify` in PowerShell or
`--skip-verify` on Linux only for development. The READY message alone is not
proof that those additional checks or the 1–3 second target passed.

Research designs, the local/physical-stand validity boundary, metrics, privacy
rules, and the evidence-capture workflow are documented in
[`app/research/README.md`](../app/research/README.md). A passing research-tooling check is
an instrumentation admission result, not an AI-performance result.
The interface-preserving migration from UERANSIM to a physical gNB and UE is
defined in [physical-5g-stand.md](physical-5g-stand.md).

A passing Phase 4C/4D run checks the following from live evidence:

1. UE1 receives `200 OK` and UE2 receives the INVITE through IMS.
2. S-CSCF triggers the SIP AS through PyHSS iFC/ISC.
3. RTPengine has two streams whose endpoints are current IMS PDU addresses.
4. Media Adapter observes RTP packets and AI Worker emits an inference tied to
   the SIP Call-ID.
5. RTP counters continue increasing while AI Worker is stopped.

The real-stream gate additionally injects deterministic Russian speech from
the UE conference bridge and proves at least two turns of `IMS PCMU -> Russian
STT -> local LLM translation -> English Piper -> RTP` in one IMS dialog. It records only
durations, language tags, character counts, backend identifiers, and latencies;
neither transcript nor generated reply is written to evidence.

The parallel-isolation gate runs `1 -> 2 -> 1` translation calls. It requires
one opaque Call-ID per audio event and one completed STT/LLM/TTS RTP reply per
call; it is a functional concurrency probe, not a capacity benchmark.

The bidirectional-interpreter gate uses separate terminated IMS legs, so raw
speech is never bridged between participants. VAD and RTP-gap detection first
assemble a pause-delimited utterance, then a bounded in-memory inference queue distributes
different calls across `AI_PROCESSING_WORKERS`. Russian source speech is sent
as English TTS only to the English leg; English source speech is sent as
Russian TTS only to the Russian leg. The report separates sentence assembly,
queue wait, STT, LLM, dispatch, TTS synthesis, and RTP playout latency.
Each call also has a bounded FIFO TTS queue, so a newly completed translation
does not truncate a reply that the subscriber is already hearing.

### Full phone-side experiment capture

Use the private experiment runner when the research question requires the
complete sound injected into and received from both subscriber endpoints:

```powershell
./scripts/run-interpreter-experiment.ps1
```

Each run creates `local/experiments/<UTC-run-id>/` with four complete WAV files,
timestamped logs for every Compose container, container/image metadata, measured
stage latency, hashes, audio format, duration, Git revision, and a PASS/FAIL
manifest. The received WAV is recorded by `pjsua` on the subscriber call leg;
it is not reconstructed from AI events. A dirty Git worktree makes the run FAIL
because its implementation cannot be identified by commit alone. The directory
contains complete speech and is intentionally excluded from Git.

The bilingual-dialogue gate generates a coherent four-turn fixture locally
with the pinned local Piper voices, places a real UE1-to-UE2 IMS call, and sends
both WAV tracks as
PCMU/8000 through the subscribers' IMS PDU sessions and RTPengine. It proves
automatic Russian/English recognition, two pseudonymous speaker streams, local
LLM normalization, and exactly four complete private transcript turns. Long
research phrases use separate env-configured VAD, duration, and RTP-gap limits;
ordinary low-latency voice-agent turns retain their shorter limits. The source
fixture is [bilingual-dialogue-v1.json](../app/tests/fixtures/bilingual-dialogue-v1.json),
generated WAVs stay under ignored `local/private/dialogue/`, and recordings stay
under ignored `local/private/recordings/`.

Regenerate the two local tracks without starting the stack:

```powershell
.\scripts\generate-bilingual-dialogue.ps1
```

The Phase 4E gate calls the configured service number from UE1 and proves that
the caller receives `200 OK`, PCMU is negotiated, the ACK reaches SIP AS, both
IMS-PDU and Voice Agent endpoints exist in RTPengine, RTP reaches the agent,
and BYE releases the SIP and media session.

To place the same call manually after registration:

```powershell
$number = (Select-String '^VOICE_TRANSLATOR_MSISDN=' app/config/lab.env).Line.Split('=', 2)[1]
$domain = (Select-String '^IMS_DOMAIN=' app/config/lab.env).Line.Split('=', 2)[1]
docker exec lab-sipue1 sh -lc "printf 'm\nsip:${number}@${domain}\n' > /tmp/pjsua-control"
```

## Implementation notes

- The IMS DNN is non-NATed; P-CSCF, S-CSCF, RTPengine, and DNS install routes
  to the env-defined UE pool through the env-defined UPF address.
- PJSUA discovers its IMS TUN by CIDR, so no `uesimtun0/1` index is assumed.
- Kamailio/PyHSS/MySQL upstream images are pinned by digest. Locally built
  Python service images use a versioned base image pinned by digest.
- Media Adapter shares RTPengine's network namespace only to observe a copy of
  relayed RTP. For concurrent calls it queries the env-defined local RTPengine
  NG endpoint by opaque Call-ID and maps the subscriber-facing relay port to
  exactly one session. The original relay remains independent of AS/AI
  availability.
- Media batches are assembled into complete VAD-delimited sentences by one
  ordered stage. Completed sentences enter a separate bounded queue and are
  processed concurrently across calls. A per-call lock prevents concurrent
  context updates; strict scheduling order under contention needs further work.
- The Voice Agent terminates only its env-defined service number; ordinary
  subscriber-to-subscriber calls remain proxied through P/I/S-CSCF.
- Voice prompts, VAD threshold, silence interval, RTP/HTTP ports, service
  identity, address, and stale-call timeout are all configured in `app/config/lab.env`.
- Custom service control uses a randomly generated token stored in a private
  Docker volume. It is not placed in Git, `app/config/lab.env`, container command lines,
  or ordinary service logs.
- Voice Agent accepts media only from the env-defined RTPengine address and
  port allocation. Translation audio is processed in memory and is not
  recorded; the analytics path receives no SIP `From`/`To` identities.
- Only a call to `VOICE_TRANSCRIBER_MSISDN` enables recording, after an audible
  disclosure. Private WAV and transcript files go to ignored
  `local/private/recordings/<pseudonymous-session>/`, never to shareable evidence.
  The raw STT text remains transient: the local LLM fixes punctuation and
  recognition errors and removes fillers, repetitions, stutters, and false
  starts before `transcript.txt` is written. It is instructed to preserve
  names, numbers, facts, meaning, and utterance order rather than summarize.
  `RECORDING_RETENTION_DAYS` declares the review/deletion deadline; deletion is
  currently an operator action, not an automatic claim.
- STT utterances, transcripts, and bounded per-call LLM history are memory-only
  and expire automatically. Model files
  use a separate persistent cache volume; the model revision and Python
  dependencies are pinned. Operational logs record sizes and timings, not
  transcript text.
- Ollama is connected only to the internal `lab-ai-backend` network and has no
  host port or IMS-core network attachment. The initializer verifies the downloaded
  GGUF SHA-256 from `app/config/lab.env` and imports the configured model tag.
- OmniVoice is deliberately not part of the lightweight default profile. It
  can be evaluated later as an independent GPU TTS factor without changing
  IMS signalling, STT, LLM, or the Voice Agent HTTP contract.
- Custom services use read-only root filesystems, no-new-privileges, bounded
  resources/logs/state, and minimal Linux capabilities. The Media Adapter is
  the only custom service retaining `NET_RAW` for RTP observation.
- IMS/UE service stdout logs are size/rotation bounded, while PyHSS file logs
  use a non-persistent tmpfs. Mongo subscriber data remains persistent; for a
  production deployment its storage must be encrypted with managed keys and a
  tested deletion/backup policy.

## Scaling and data protection

The implemented profile is a hardened single-host development baseline. It is
not presented as a production multi-tenant deployment. The compared production
options, trust boundaries, data-retention rules, migration order, and remaining
decisions are in [the security hardening review](hardening/hardening.md) and
[the full proposal](hardening/proposals/scalable-private-service-boundary.md).

The recommended production direction is dialog-affine SIP AS replicas, a
durable call-state owner, an RTPengine shard pool, workload identity with mTLS,
KMS/HSM-backed secrets, bounded metadata queues, and independently autoscaled
AI workers. Dedicated per-tenant cells are reserved for tenants whose legal or
contractual isolation requirements justify separate compute, keys, and data.

## If the simulated radio link stops

A running container does not prove a working PDU session. If UE logs report
`signal lost` / `Service Request` timeouts and gNB reports
`Discarding RRC Setup Request, UE context already exists`, SIP retransmissions
and a missing BYE can originate below the application layer. Inspect the UE/gNB
logs and run `app/tests/integration/verify-ims.sh` before blaming an AI queue.

With no user calls active, restart `gnb ue1 ue2` through `scripts/compose.ps1`,
then recreate `sipue1 sipue2` so their sockets bind the current IMS PDU addresses.
Repeat registration and the failed gate. Do not erase database/model volumes.
A failed run remains failed; a later retry is separate evidence.

## Plain Digest call without AS/AI

On an idle base-only stand, run these gates serially from the repository root:

```powershell
python app/tests/integration/verify_plain_call.py
python app/tests/integration/verify_plain_call.py --caller 2
python app/tests/integration/verify_plain_call.py --mute-ue 1
```

The gate requires AS/AI services stopped and no active relay sessions. It takes
the stand lock, temporarily changes both iFC paths, restarts S-CSCF and SIP
clients, then restores their normal profiles. Do not use it during other calls.
Each attempt writes private WAV/log evidence and `result.json` under
`local/private/plain-call-<timestamp>`. `sip1.log` denotes the caller trace and
`sip2.log` the callee trace; `receive1.wav` always denotes UE1.
The muted-source scenario passes only when the opposite receiver fails its
waveform check while the other receiver and signalling pass. This validates
fault detection; it is not a successful two-way media call.

## Isolated AKA registration probe

Build the [OPc-capable SIPp image](sipp-aka-provenance.md), then use an idle stand:

```powershell
python app/tests/integration/verify_aka_registration.py
python app/tests/integration/verify_aka_registration.py --bad-response
```

These commands run serially under the stand lock. Both Digest clients are stopped
and S-CSCF's cached contacts are cleared before the probe. SIPp uses each UE's
current IMS PDU route and its independent IMS K/OPc. The negative scenario sends
a deliberately invalid response from UE1 while UE2 still registers normally.
The probe restores ordinary clients and checks fresh Digest registration afterwards.

SIP traces, the credential-bearing generated scenarios and Cx PCAP remain under
`local/private/aka-register-<timestamp>`. A registration PASS is not a continuous
AKA call, SQN replay/resync acceptance, Gm protection or full T03 compliance.
Consult each result's separate Cx metadata status before making a wire-correlation claim.

## Continuous AKA call gate

On an idle base stand with AS/AI stopped, run these gates serially:

```powershell
python app/tests/integration/verify_aka_call.py
python app/tests/integration/verify_aka_call.py --caller 2
```

Each UE keeps one SIPp process/socket from AKA registration through the dialog,
with different REGISTER and INVITE Call-IDs. A separate RTP helper in the same
UE network namespace sends and receives PCMU/8000 using the negotiated SDP.
The gate requires correlated Cx/SIP authentication, complete SIP dialog, IMS PDU
media routes, call-specific relay lifecycle and opposite-source receiver WAVs.
It temporarily installs a no-AS iFC and restores the original profile and fresh
Digest clients afterwards. `SIP_AKA_RESTORE_TIMEOUT_SECONDS` bounds the wait
for fresh REGISTER 200 (default 90 seconds, allowing a native PJSUA retry);
`restored_clients` records response codes, including any transient failures. Inspect both `status` and `cleanup` in private
`local/private/aka-call-<timestamp>/result.json`; retain failed attempts.

The receiver boundary is decoded UDP RTP, not speaker playback. This gate does
not establish protected Gm, persistent UE SQN/replay/resync, policy/QoS, or the
translation latency SLA. Scenario mechanics are documented in the
[continuous-client design](aka-continuous-client-spike.md).

## AKA registration lifecycle gate

On an idle stand, run serially with the other integration gates:

```powershell
python app/tests/integration/verify_aka_lifecycle.py
```

One SIPp process per UE performs initial AKA registration, refresh and explicit
`Expires: 0` deregistration, using a fresh challenge at each step. The gate
requires matching Cx MAA vectors, a current S-CSCF Contact after registration,
a renewed expiry after refresh, and removal after deregistration. Checkpoint
pauses are controlled by `SIP_AKA_LIFECYCLE_CHECKPOINT_SECONDS` (20 seconds)
and `SIP_AKA_LIFECYCLE_FINAL_SECONDS` (5 seconds). Physical Contact removal
is bounded by `SIP_AKA_REGISTRAR_DELETE_TIMEOUT_SECONDS` (210 seconds): the
S-CSCF's deletion delay and periodic timer can retain tombstones in its RPC.
Both ordinary SIP clients stay stopped during this observation. Private XML, SIP traces, PCAP,
registrar snapshots and verdict are retained under `local/private/aka-lifecycle-*`.
Normal Digest clients are restored and independently checked afterwards.

This scenario does not cover passive expiry, old-contact call rejection,
address change, nonce replay, persistent UE SQN, AUTS resynchronization or Gm
security. Generic SAR transactions are not a verified assignment-subtype claim.

## Calls to inactive AKA registrations

Run on an idle base stand with AS/AI stopped, serially:

```powershell
python app/tests/integration/verify_aka_inactive_call.py --mode deregister
python app/tests/integration/verify_aka_inactive_call.py --mode expire
```

`--callee 1|2` selects the UE made inactive. Its SIPp process remains alive at
the former Contact. Explicit deregistration waits for registrar removal; passive
expiry first waits for a nonpositive remaining lifetime and immediately tests
call rejection, then separately waits for physical record removal. Exact
IMS-IP/SIP-port UDP binding is checked before and after the call. The other UE
then registers via AKA and calls it; this no-AS profile expects a transaction-
bound 404 and non-2xx ACK, no delivered INVITE at the old Contact, and no leaked
relay session. Passive expiry requests `SIP_AKA_EXPIRY_SECONDS` (30 seconds);
`SIP_AKA_INACTIVE_HOLD_SECONDS` keeps the listener alive during timer cleanup.
Physical passive cleanup has its own `SIP_AKA_PASSIVE_DELETE_TIMEOUT_SECONDS`
bound (390 seconds): this Kamailio version can require four 90-second timer
passes. The callee hold is 600 seconds. An expired record may remain visible
with zero or negative remaining seconds; that is not an active registration.

Evidence stays in `local/private/aka-inactive-<mode>-*`. Its Cx capture covers
registration authentication up to the caller's REGISTER 200; it does not claim
to validate subsequent LIR/LIA or unregistered SAR subtypes. Original iFC and
ordinary Digest clients are restored. Inspect separate scenario and cleanup
verdicts; a caller timeout or 500 is not the expected unreachable result.

## Real IMS PDU recovery

```powershell
python app/tests/integration/verify_pdu_recovery.py --ue 1
```

Run serially with the base stand idle and AS/AI stopped. This gate releases the
selected UE's actual IMS PDU session (selected by DNN, not a fixed PSI) and
observes UERANSIM's automatic re-establishment. It requires a different assigned
IMS IPv4 address, new TUN ifindex, correct SIP/RTP routes, a restarted normal SIP
client and a fresh REGISTER 200. The other UE and the selected UE's non-IMS
session must retain their sampled state. A same-address allocation does not
pass the address-change gate. Cleanup restores usable service; it does not force
the old dynamically assigned address back into the pool.

CLI requests have `UE_CLI_TIMEOUT_SECONDS` bounds. Before using `nr-cli`, the gate
checks its registry against the current nr-ue PID, process start and owned
loopback UDP socket. Proven stale entries are moved into a unique
`/tmp/UERANSIM.proc-table-quarantine/` backup directory inside the UE container;
ambiguous ownership fails. This handles stale records whose PID was reused after
a container restart. Private receipts and PDU/network snapshots remain under
`local/private/pdu-recovery-*`.

This is access recovery evidence, not a complete IMS mobility verdict. A new
Contact can coexist with an old Contact. Separate acceptance must explicitly
remove or expire the old binding and correlate the subsequent call with the
same registration epoch. The ordinary AKA call gate restarts S-CSCF, so a later
PASS demonstrates a fresh call on the changed PDU address, not stale-binding
replacement. PFCP wire correlation and radio mobility are separate checks.

## Stop

```powershell
.\scripts\compose.ps1 down
```

Named volumes are preserved, including subscriber data, model caches and the
service-control token. `down -v` removes all declared named volumes, including
model caches; it is not an ordinary restart command. Host-side `local/` files
are separate and remain on disk.
