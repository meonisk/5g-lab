# Первое знакомство и работа со стендом

Это лаборатория телефонных звонков в сети 5G с локальным переводом RU ↔ EN
и расшифровкой речи. Сначала можно запустить её целиком на одном компьютере,
без настоящей базовой станции, SIM-карты и телефона.

## Что вы получите

Проект запускается командами в терминале. Веб-интерфейса для звонков и кнопки
«говорить в микрофон» в текущем составе нет. Docker запускает несколько сервисов:

| Часть | Простыми словами |
| --- | --- |
| OAI — ядро 5G | Подключает абонентов к сети и выдаёт им сетевые сессии |
| UERANSIM | Изображает базовую станцию и два абонентских устройства |
| IMS | Регистрирует телефонных абонентов и соединяет звонки |
| RTPengine | Передаёт звук между участниками и голосовым сервисом |
| AI Worker | Распознаёт речь и переводит текст |
| Voice Agent | Превращает текст перевода в голос |

Локальные SIP-клиенты работают без звуковой карты (`--null-audio`): подают
синтетическую речь из WAV. Поэтому успешный тест сам по себе не включит звук
в динамиках вашего компьютера. Записи воспроизводятся отдельно; работа через
микрофон настоящего телефона требует [подключения устройства](native-phone.md).

## Какой сценарий выбрать

- **Впервые знакомитесь с проектом:** установите инструменты и поднимите сначала
  только сеть/IMS по [quickstart](quickstart.md). GPU для этого не нужен.
- **Нужен текущий полный набор автоматических проверок:** используйте исходный
  режим с Qwen. Он тоже работает на CPU, но требует больше ресурсов.
- **Ограничена память, нужны перевод и транскрипция:** выберите `compact`.
  Нужна отдельная подготовка OPUS; полный телефонный сценарий этого профиля
  ещё требует проверки. `minimal` не равноценен по качеству.
- **Ядро 5G уже есть в другом проекте:** сразу переходите к
  [подключению IMS + AI](partner-integration.md), не запускайте второе ядро.

Дальше описана работа **с локальными эмуляторами**. Команды `lab-sipue1/2`
не относятся к внешним телефонам.

## Где выполнять команды

«Корень репозитория» — папка с `README.md`, `docker-compose.yml`, `app/` и
`scripts/`. Имя папки может быть `5g-lab` после клонирования или `lab-docker`
в уже существующем рабочем каталоге. Не создавайте второй клон внутри первого.

На Windows используйте PowerShell для команд Python/Docker и `.ps1`.
Для команд `bash ...` откройте **Git Bash в той же папке**. Это не отдельная
установка проекта в WSL. На Linux используйте Bash.
Блоки команд копируйте без строк с тройными обратными кавычками.

Перед новой рабочей сессией включите Docker, перейдите в корень и активируйте
окружение: `.\.venv\Scripts\Activate.ps1` на Windows либо
`source .venv/bin/activate` на Linux. Создавать `.venv` повторно не нужно.
Установка инструментов, окружения и запуск: [пошаговая инструкция](quickstart.md).

## Первый вызов после запуска AI

Сначала убедитесь, что базовый запуск завершился без ошибки и оба абонента
зарегистрированы. Для облегчённого режима дополнительно дождитесь `healthy`
у AI Worker и Voice Agent. `Up` означает работающий процесс, но не успешный звонок.
Завершившийся с кодом 0 одноразовый загрузчик/генератор токена — нормальное состояние.

На свободном стенде, **по одной команде**, в Git Bash или Linux Bash:

```bash
bash app/tests/integration/verify-ims-registration.sh
bash app/tests/integration/verify-voice-agent.sh
```

Первая команда проверяет регистрацию двух SIP-клиентов. Вторая сама звонит
голосовому сервису, проверяет приветствие, сигнализацию и передачу RTP, завершает
вызов. Ищите итоговый `PASS`; при `FAIL` остановитесь и изучите
[диагностику](running.md#диагностика-и-перенос). Проверка Voice Agent завершает
существующие RTP-сессии, поэтому не запускайте её во время чужого разговора.

Это проверка голосового входа, а не качества перевода. Для исходного режима
Qwen дополнительно выполняются:

```bash
bash app/tests/integration/verify-real-ai-stream.sh
bash app/tests/integration/verify-transcription-recording.sh
python app/tests/integration/check_bidirectional_interpreter.py
```

Первая проверка подаёт русские реплики и ожидает английский голосовой ответ.
Вторая звонит на услугу записи и проверяет текст. Третья создаёт два языковых
вызова и проверяет перевод в обе стороны; нужны WAV, подготовленные полным
launcher. Название `verify-real-ai-stream.sh` историческое: оно не означает,
что экспериментальный streaming включён.

В `compact/balanced/minimal` не используйте проверку LLM-нормализации как
проверку raw-транскрипции: она обращается к Ollama и ожидает другую функцию.
Для CPU-профилей нет отдельной полностью принятой последовательности всех
этих телефонных тестов. Ручная работа с услугами описана ниже; результаты
фиксируйте отдельно от baseline. Полный перечень проверок — [running.md](running.md).

## Как вызвать услугу вручную

Оба локальных клиента уже зарегистрированы после базового запуска. Номера
берутся из `lab.env`; по умолчанию:

| Номер | Что происходит |
| --- | --- |
| 1001 / 1002 | Обычные тестовые абоненты |
| 1003 | Говорящий по-русски получает перевод на английский |
| 1004 | После уведомления речь записывается и расшифровывается |
| 1005 и 1006 | Два участника переводчика: русский звонит на 1005, английский на 1006; каждый слышит свой язык |

Пример для транскрипции, **Git Bash или Linux Bash**, при запущенных IMS и AI:

```bash
docker exec lab-sipue1 sh -lc 'printf "m\nsip:%s@%s\n" "$VOICE_TRANSCRIBER_MSISDN" "$IMS_DOMAIN" > /tmp/pjsua-control'
docker logs --since 1m lab-voice-agent
```

Дождитесь строки `reason=greeting state=sent` для нового вызова. Синтетическая
дорожка стандартного клиента может уже подаваться автоматически. Если нужны
управляемые порции аудио, сначала посмотрите список аудиопортов PJSUA:

```bash
docker exec lab-sipue1 sh -lc 'printf "cl\n" > /tmp/pjsua-control'
docker logs --tail 80 lab-sipue1
```

В штатном свежем клиенте проигрыватель обычно имеет порт 1, а звонок — 4.
Используйте фактические номера из списка. Следующие команды подходят именно
для пары 1 → 4: `cc` подключает проигрыватель к звонку, `cd` отключает.

```bash
docker exec lab-sipue1 sh -lc 'printf "cc\n1\n4\n" > /tmp/pjsua-control'
```

Дайте проиграть несколько секунд, затем отключите источник, чтобы AI увидел паузу:

```bash
docker exec lab-sipue1 sh -lc 'printf "cd\n1\n4\n" > /tmp/pjsua-control'
docker logs --since 2m lab-ai-worker
```

Дождитесь обработки и появления записи. Завершение звонка:

```bash
docker exec lab-sipue1 sh -lc 'printf "ha\n" > /tmp/pjsua-control'
```

Для RU → EN в первой команде замените `VOICE_TRANSCRIBER_MSISDN` на
`VOICE_TRANSLATOR_MSISDN`. Результат идёт по RTP обратно клиенту, а не в динамики
хоста. Для двустороннего перевода нужны отдельные русская и английская WAV-дорожки:
два стандартных клиента с одной русской тестовой фразой не заменяют такой сценарий.
Подготовленный сценарий описан в [руководстве оператора](running.md).

## Где найти результат

На машине, где работает Docker, откройте `local/private/recordings/` в корне
репозитория. Для обработанного звонка на 1004 появляется каталог с идентификатором:

```text
local/private/recordings/<session-id>/
  README.txt          уведомление о приватной записи
  transcript.txt      распознанный текст реплик
  turn-0001.wav       звук первой сохранённой реплики
  turn-0002.wav       следующая реплика, если она была
  manifest.jsonl      метаданные: язык, длительность, вид транскрипции
```

WAV откройте аудиоплеером, текст — редактором UTF-8. Каждая строка JSONL —
отдельная реплика. В облегчённом режиме ожидается `transcript_kind=raw_asr`;
в baseline при успешной нормализации — `llm_normalized`. Отсутствие каталога
не считается успехом: проверьте уведомление, поступление речи, логи AI и
`RECORDING_ENABLED`. Записывается услуга 1004, а не каждый обычный звонок.
Эти файлы содержат данные разговора и остаются вне Git.

## Завершить работу и вернуться позже

Для Qwen: `./scripts/compose.ps1 down` в PowerShell или
`./scripts/compose.sh down` в Bash. Для compact:

```bash
python scripts/compose_ai.py --mode compact down
```

Без `-v` базы и кэши моделей сохранятся, файлы `local/` также останутся.
Закрытие терминала само по себе не останавливает контейнеры. Для выхода из
просмотра `logs -f` нажмите Ctrl+C — это прекращает только просмотр.
Следующий запуск выполняется тем же сценарием из [quickstart](quickstart.md).
Не запускайте обычный полный launcher поверх compact, если хотите сохранить
облегчённый режим.
