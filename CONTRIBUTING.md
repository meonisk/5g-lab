# Командная разработка

Все команды выполняются из корня репозитория на Linux.

## Ежедневный цикл

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
python scripts/check.py
docker compose --env-file app/config/lab.env build ai-worker
docker compose --env-file app/config/lab.env up -d --no-deps ai-worker
```

После изменения протокола, маршрутизации или аудиоконвейера пересоберите
затронутые образы и выполните подходящие проверки из `app/tests/integration/`.
Они создают звонки на общем стенде: запускайте их строго по одной.

## Правила изменений

- Документацию, комментарии и сообщения оператору пишите по-русски. Имена файлов,
  CLI-параметры, переменные окружения, поля JSON и протокольные значения сохраняйте
  совместимыми. Уведомления правообладателей и сторонние исходники — в оригинале.
- Корневой README короткий: назначение, запуск, навигация. Подробности — в `docs/`.
- Один модуль — одна понятная задача. Максимум **300 логических строк** на
  собственный исходный файл или YAML; пустые строки и комментарии не считаются,
  многострочное выражение Python считается одной строкой.
- Отделяйте пустыми строками получение данных, проверку, изменение состояния и
  внешнее действие. Комментируйте причину, протокольный контракт, обработку отказа и
  правила параллельности, а не синтаксис.
- Все параметры запуска, адреса и ключи — только в `app/config/lab.env`; `check.py`
  отклоняет адреса, IMSI и домен в коде. Значения протокола (PCMU 8 кГц, структура
  RTP) являются контрактом кода.
- `settings.py` хранит конфигурацию AI Worker, `runtime.py` — изменяемое состояние.
- Интеграционные проверки находятся только в `app/tests/integration/`; каждая
  начинается с описания того, что она проверяет. Не добавляйте проверку, которая
  повторяет существующую.
- `app/infrastructure/vendor/` — сторонние файлы с provenance и лицензией; лимит 300
  строк к ним не применяется, правки upstream документируйте в `PROVENANCE.md`.
- WAV, расшифровки, кэш моделей и результаты запусков в Git не добавляются.
- В описании изменения укажите поведение до и после и реально выполненные проверки.
  Обновляйте `CHANGELOG.md` в разделе `Unreleased` с префиксами Conventional Commits
  (`feat`, `fix`, `refactor`, `docs`, `test`, `build`). Работайте в отдельной ветке.

## Проверки перед review

`python scripts/check.py` проверяет индекс Git (права shell-файлов, приватные файлы,
ключи), размер и синтаксис файлов, окончания строк shell-скриптов, локальные ссылки
Markdown, отсутствие топологии вне `lab.env`, затем ruff и unit-тесты. Контейнеры он
не запускает. Сервисные библиотеки ставятся в Docker-образах; на хосте нужны только
зависимости из `requirements-dev.txt`.
